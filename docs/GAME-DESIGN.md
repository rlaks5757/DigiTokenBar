# 게임 설계 — 수집 · 육성 · 진화

DigiTokenBar 의 게임 규칙. 진화 데이터는 [`EVOLUTION.md`](./EVOLUTION.md) 참고.

**상위 원칙: upstream(PokeTokenBar)의 토큰 경제를 그대로 쓴다.** 실측 사용량 기반으로
튜닝된 값이라 근거 없이 바꾸지 않는다. 바꾸는 지점만 아래에 명시한다.

---

## 1. 기본 루프 (upstream 그대로)

```
토큰 사용 → 알 부화(5M) → 성장 → 진화 → 졸업 → 도감 등록 → 새 알
```

| 상수 | 값 | 비고 |
|---|---|---|
| 알 부화 임계 | 5,000,000 | 초과분은 부화체 성장에 이월 |
| 졸업 총량 (common) | 750,000,000 | |
| 졸업 총량 (uncommon) | 1,875,000,000 | common × 2.5 |
| 졸업 총량 (rare) | 3,000,000,000 | common × 4 |
| 졸업 총량 (legendary) | 6,000,000,000 | common × 8 |
| 재육성 배율 | 2 | 같은 종 반복 시 |
| 난이도 슬라이더 | 0.1 ~ 2.0 (기본 1.0) | 로그 매핑 |

### 단계별 임계 계산 (upstream 공식 유지)

k개 형태를 가진 라인에서 i번째(1-based) 형태의 성장 비용:

```
threshold(i) = T · i / (k(k+1)/2)     → 합계 = T
```

**졸업 총량 T 는 진화 단계 수와 무관하게 동일하다.** 단계가 많으면 각 단계가 싸진다.
→ Tailmon 라인(k=2)과 Agumon 라인(k=4)의 졸업 비용이 같다. 의도된 동작이다.

## 2. 🚨 희귀도 — upstream 방식을 쓸 수 없다

### 문제

upstream 은 PokéAPI `capture_rate` 로 희귀도를 매긴다. **디지몬에는 이에 대응하는 수치가 없다.**

초기 안은 "라인의 최종 레벨 = 희귀도"였다. **실측 결과 이 방식은 상점을 망가뜨린다:**

| 최종 레벨 | 라인 수 | → 희귀도 | 결과 |
|---|---|---|---|
| Adult | 4 (33%) | uncommon | |
| Perfect | 6 (50%) | rare | |
| Ultimate | 2 (17%) | legendary | |
| — | **0** | **common** | ⚠️ **저등급 풀이 비어버림** |

문제 두 가지:
1. **`common` 라인이 0개** → 보증 없는 기본 알이 뽑을 저등급 후보가 없다.
2. **`rare` 이상이 8/12(67%)** → 희귀 알(4.00B)의 "희귀 이상 보증"이 사실상 무보증이다.

즉 **가격 사다리(1B / 2.5B / 4B) 밑에 분포가 없다.**

### 결정: 라인별 희귀도 **수기 지정**

12라인뿐이므로 파생하지 말고 직접 배정한다.
(ANALYSIS.md 의 "크롤러보다 수기 테이블이 낫다" 판단과 동일한 논리)

| 희귀도 | 라인 | 근거 |
|---|---|---|
| common | Piyomon, Tentomon, Palmon, Gomamon | 01 조연 4라인 |
| uncommon | V-mon, Wormmon, Hawkmon, Armadimon | 02 파트너 4라인 |
| rare | Patamon, Tailmon | 작중 비중 높음 |
| legendary | Agumon, Gabumon | Ultimate 보유 + 오메가몬 부모 |

→ 4 / 4 / 2 / 2 분포. 가격 사다리가 정상 동작한다.

> **희귀도는 라인 단위 속성이다.** 개체 레벨이 아니다.
> Agumon 은 Child 지만 legendary 라인이므로 졸업 총량 6B 를 따른다.

### 랜덤 풀 규칙 — 12라인용으로 재정의

upstream `CollectionWeight.adjusted(_:isCollected:)` 는 이미 수집한 종의 가중치를 **1/2** 로 낮춘다.
**이건 649종 로스터 기준으로 튜닝된 값이다.** 12라인에서는 1/12 → 1/11.5 수준이라 사실상 무의미하다.

**결정: 도감 미완성 동안 이미 졸업한 라인을 랜덤 풀에서 제외한다.**

- 12라인을 다 모을 때까지는 **중복 없는 ≤12회 수열**이 된다.
  (균등 1/12 쿠폰 수집이면 특정 2종에 기대 18개 알이 필요하다 — 무한 대기의 원인)
- 도감 완성 후에는 전체 풀로 복귀하고, 그때부터 `repeatGrowthMultiplier = 2` 가 적용된다.
- **등급 보증 알에도 동일하게 적용한다** — 보증 풀에서 졸업분을 뺀다.

#### 제외 기준은 "졸업"이지 "부화"가 아니다

**중복이 발생할 수 있는 경로가 두 개 있다. 둘 다 의도된 동작이다.**

| 경로 | 도감 등록 | 풀에서 제외 | 같은 라인 재출현 |
|---|---|---|---|
| 졸업 | ✅ | ✅ | ❌ (도감 완성 전) |
| **알 리롤 (1.00B)** | ❌ | ❌ | ✅ **가능** |
| **육성 중 포기/교체** | ❌ | ❌ | ✅ **가능** |

upstream 은 리롤한 개체를 "뽑은 적 없던 것처럼" 처리한다 — 도감에도 확률에도 영향이 없다.
**이 성질을 유지한다.** 리롤이 풀을 줄이면 1.00B 로 도감을 깎는 파밍이 되기 때문이다.

> 즉 **"안 뽑힌 라인이 다시 나오는 일"은 없지만, "버린 라인이 다시 나오는 일"은 있다.**
> 리롤은 마음에 안 드는 개체를 넘기는 수단이지, 특정 라인을 겨냥하는 수단이 아니다.

#### 죠그레스·아머 결과는 풀에 영향을 주지 않는다

- 죠그레스 결과(Omegamon 등)와 아머체는 **도감에 등록되지만 알에서 나오지 않는다.**
  랜덤 풀의 단위는 **12개 Child 라인**이다.
- 같은 라인 2회차 육성(§4 아머↔죠그레스)은 **도감 완성 후에만** 가능하다.
  미완성 동안에는 그 라인이 풀에서 빠져 있기 때문이다.

> 이 규칙이 "파피몬이 안 나와서 못 넘어간다"를 구조적으로 막는다.

## 3. 죠그레스 — 도감 게이팅

### 문제

현재 앱은 **육성 중인 개체가 1마리**다. 죠그레스는 2마리가 필요하다.

### 결정: 도감 졸업 기록을 파트너로 인정

```
[육성 중] XV-mon — 죠그레스 임계 도달
[도감]    Stingmon 졸업 기록 있음  →  죠그레스 활성화
          XV-mon + Stingmon → Paildramon
```

**규칙:**
- 파트너는 **소모되지 않는다** — 도감은 재고가 아니라 기록이다.
- 파트너 기록이 없으면 버튼 비활성 + `"Stingmon을 먼저 졸업시켜야 합니다"` 안내.
- `(A, B)` 는 **순서 무관** — 정렬된 키로 정규화해 조회.

### ✅ 죠그레스 결과는 도감에 졸업 등록된다

**이게 없으면 Paladin Mode 가 영구 도달 불가다.** Paladin Mode 의 부모
(Imperialdramon FM, Omegamon)는 **둘 다 죠그레스 결과물**이기 때문이다.

도달 경로:
```
1. Agumon 라인 졸업 → War Greymon 기록
2. Gabumon 라인 졸업 → Metal Garurumon 기록
3. 죠그레스 → Omegamon (도감 등록됨)
4. V-mon/Wormmon 라인 → Paildramon → Imperialdramon FM (도감 등록됨)
5. Imperialdramon FM + Omegamon → Paladin Mode   ← 최종 보상
```

### 파트너 조달 — 등급 보증 알

**보증은 "그 등급 이상"이지 "그 등급대"가 아니다.**
upstream 판정은 `line.rarity.sortRank < tier.sortRank` 로 **하한 미달만 거른다.**

| 알 | 가격 | 실제 풀 | 라인 수 |
|---|---|---|---|
| 기본 (보증 없음) | 1.00B | 전체 | 12 |
| 고급 이상 | 2.50B | uncommon+rare+legendary | 8 |
| 희귀 이상 | 4.00B | rare+legendary | 4 |

**결과: 상위 등급일수록 겨냥하기 쉽고, 중간 등급이 가장 어렵다.**
위에서 희석되지 않는 건 최상위 티어뿐이기 때문이다.

- `legendary`(Agumon·Gabumon) = 오메가몬 부모 2종.
  희귀 알 4.00B 로 **1/4** → 둘 다 모으는 데 기대 ~6개.
- `uncommon`(02 파트너 4라인)은 고급 알을 사도 8라인 중 4라인이라 **50%**.
  → **실질 병목은 Agumon·Gabumon 이 아니라 V-mon·Wormmon 이다.**
  Paildramon → Imperialdramon FM → Paladin Mode 경로가 여기에 걸린다.

## 4. 아머 진화 — 상점 아이템

**디지멘탈을 상점에서 팔고, 사용하면 Child 에서 아머형으로 분기한다.**

### ✅ 확정(2026-09-24 개정): 아머는 **자유 전환 오버레이**다

**디지멘탈은 언제든 쓸 수 있고, 언제든 되돌릴 수 있다.** 한 개체로 아머체와 성숙기를 모두 본다.

```
V-mon → (용기의 디지멘탈) → Fladramon → (아머 해제) → V-mon → (성장) → XV-mon
```

이전 개정(아래 "폐기된 규칙")은 아머를 **그 개체의 졸업**으로 규정했다. 사용자가
자유 전환으로 방향을 확정하면서 그 모델과 거기서 파생된 규칙들이 함께 폐기됐다.

#### 상태 표현 — 사다리는 건드리지 않는다

아머는 `MonState.armorID: Int?` **표시 오버레이**다. 정규 사다리 상태
(`pathIDs` / `stageIndex` / `usedAtStage` / `plannedPathIDs` / `totalForms` / `profile` /
`hasGrowthBoost`)는 착용·해제·교체 어느 쪽에서도 **전부 불변**이다.

- 성장 축(`currentID`)은 계속 사다리 종을 가리킨다. 표시 축(`displayID`)만 아머체가 된다.
- 되돌리기 = `armorID = nil`. 별도 복원 로직이 없다 — 정규 진화 경로는 애초에 손대지 않았다.
- **k(=`totalForms`)를 바꾸지 않는다.** 이전 개정의 `k = stageIndex + 1` 규칙은 아머형을
  최종 형태로 만들기 위해서만 존재했으므로 자유 전환에서는 불필요해졌다. 덕분에 임계값
  재계산·`rareCandyStageCosts` 어긋남·"3/4 → 3/5" 표기 변동이 전부 사라진다.
- 결과적으로 아머 착용 중에는 **스프라이트는 아머체인데 진행 표시는 사다리 기준**이다.
  버그가 아니다 — 성장은 실제로 사다리에서 일어나고 있고, 진행 표시는 그 사실을 말한다.

#### 아머 착용 중 정규 진화 조건을 채우면 — 자동 해제 후 진화

성장은 아머 착용 중에도 멈추지 않는다. 임계에 도달하면 아머가 저절로 풀리며 사다리가
전진한다(진화 후에는 성장기가 아니게 되므로 재착용도 자연히 불가). 진화 후 아머체가
남아 외형과 종이 어긋나는 상태를 만들지 않는다.

#### 디지멘탈은 비소모(열쇠형)다

한 번 사면 계속 쓴다. 착용/해제를 반복해도 개수가 줄지 않는다. 재고 0 이라 되돌리지 못하는
상태가 생기지 않는다.

#### 왕복 파밍은 불변조건 하나로 닫힌다

> **불변조건: 아머 착용/해제/교체는 위 7개 사다리 필드 중 어느 것도 변경하지 않는다.**

- XP 는 착용 여부와 무관하게 사다리에만 쌓인다 → 왕복해도 진행도 이득 0
- `phaseThreshold` 가 읽는 `totalForms`/`stageIndex`/`hasGrowthBoost` 가 전부 불변 → 임계값 조작 불가
- `usedAtStage` 불변 → 해제 시 XP 리셋/이월로 이득 보는 경로 없음
- `profile` 불변 → 성장 프로필 재굴림 불가

아래 "아머는 토큰을 아껴주지 않는다" 전제가 자유 전환 하에서도 그대로 유지되므로,
디지멘탈 저가 책정(도감 확장 콘텐츠 가격)도 그대로 유효하다.

> ⚠️ **아머는 토큰을 아껴주지 않는다.** `graduationTotal` 은 단계 수 k 와 **무관하게 동일**하다
> (공식이 그렇게 설계됐다 — k가 크면 단계당 비용이 싸질 뿐 합은 T로 같다).
> 오버레이 모델에서는 k 자체를 바꾸지 않으므로 이 성질이 더 단순하게 성립한다.
>
> 아머의 이득은 **도감 확장**과 **한 개체로 두 갈래를 다 보는 것**이다.
> 따라서 디지멘탈 가격은 "단축분 회수"가 아니라 **도감 확장 콘텐츠 가격**으로 책정한다.

#### 도감 등록 — 별도 기록이 필요하다

아머체는 `pathIDs` 에 들어가지 않으므로 `dexSpecies`/`ownsSpecies` 가 저절로 잡지 못하고,
`armorID` 에서 유도하면 되돌리는 순간 기록이 증발한다(도감의 "쌓이기만 한다" 약속 위반).

→ **아머 진화 시 `DexEntry` 를 하나 추가한다**(`armoredAt: Date?` 가 판별자, `releasedAt` 과
같은 축). 해제해도 지우지 않고, 같은 아머체 재착용은 중복 줄을 쌓지 않는다.
`collectedFinals` 는 건드리지 않는다 — 끝까지 키운 게 아니고, 부화 가중치에 영향을 주면 안 된다.

#### 되돌리기 컨트롤은 Home 에 둔다

가방은 `ownedItems`(개수>0)만 그리므로, 디지멘탈을 하나도 갖지 않은 상태(기기 간 세이브 등)에선
카드 자체가 없어 되돌릴 수단이 사라진다. Home 의 컴패니언 영역에 "아머 해제"를 둔다.

### 폐기된 규칙 (2026-09-24 이전)

아래는 **더 이상 유효하지 않다.** 기록으로만 남긴다.

| 폐기된 규칙 | 폐기 사유 |
|---|---|
| 아머 분기의 `k = stageIndex + 1`, 아머형이 그 라인의 최종 형태 | 오버레이는 `totalForms` 를 건드리지 않는다 |
| 아머형 도달 = **그 라인의 졸업**, 도감 등록 후 새 알로 | 자유 전환엔 졸업이 없다 → `DexEntry` + `armoredAt` 이 대체 |
| **퇴화(devolution) 기능을 넣지 않는다** | 아머 해제가 곧 되돌리기다(단, 정규 사다리 자체의 퇴화는 여전히 없다) |
| 진화 트리 UI 는 열람 전용, 임의 진화/퇴화 버튼 없음 | Home 에 아머 해제 컨트롤을 둔다. 트리 UI 자체는 여전히 열람 전용이다 |
| 2회차 육성 모델(1회차 Fladramon 졸업 / 2회차 XV-mon 졸업) | 한 개체로 둘 다 보므로 같은 라인을 두 번 키울 이유가 없다 |

**`repeatGrowthMultiplier = 2` 경제가 이 경로에서 빠진다.** 재육성 배율 자체는 남아 있지만
(다른 라인을 다시 뽑는 경우), "아머와 성숙기를 둘 다 보려고 같은 라인을 2회 키운다"는 동기는
사라졌다.

**죠그레스 파트너 판정**은 여전히 도감 기록을 본다(§3). 자유 전환에서는 한 개체가
XV-mon 까지 정규 진화한 뒤 그 기록을 남기면 되므로, 아머를 먼저 써도 경로가 막히지 않는다.

### ⚠️ 문서 부채: 풀 제외 조건 강화는 **구현되지 않았다**

아래 "죠그레스 경로 미완 = 미수집" 규칙은 **문서에만 있고 코드에 없다.**
`CompanionStore.chooseBase()` 는 하드 제외를 하지 않고 `CollectionWeight.adjusted(_:isCollected:)`
로 가중치를 절반으로 깎을 뿐이다(`hasCollectedFinal(forBaseID:)`).

자유 전환에서는 "아머 졸업이 죠그레스 경로를 잠근다"는 문제 자체가 사라지므로 이 규칙의
**근거도 함께 소멸했다.** 구현할 이유가 없어졌고, 아래 표는 기록으로만 남긴다.

<details>
<summary>폐기된 규칙 원문 (기록용)</summary>

아머를 먼저 써도 죠그레스가 막히지 않도록 **풀 제외 조건을 강화한다.**

**규칙: 라인이 풀에서 빠지려면 아래 둘 다 만족해야 한다.**
1. 그 라인을 졸업시킨 기록이 있다
2. **그 라인이 죠그레스 부모로 필요한 성숙기(Adult) 기록을 갖고 있다** — 해당 시에만

**적용 대상은 죠그레스 부모가 되는 라인뿐이다.** ([`EVOLUTION.md` §3](./EVOLUTION.md))

### 🚨 아머 선택은 결정적(deterministic)이다

upstream 의 분기 선택은 `CollectionWeight.adjusted(_:isCollected:)` 로
**가중 랜덤**이다(이미 수집한 종은 가중치 1/2).

**아머 진화는 이 가중치를 우회한다.** 사용자가 디지멘탈을 골라 쓰는 행위이므로,
`(Child, 디지멘탈)` 복합키가 결과를 **확정**한다. 랜덤 없음.

> 정규 진화 분기는 기존 가중 랜덤을 그대로 쓴다. 우회는 아머 경로 한정.

### 디지멘탈 아이템

- `ItemKind` enum 에 10종이 들어 있다(`rareCandy` + 디지멘탈 9종).
- **성실 디지멘탈은 V-mon·Armadimon 양쪽에서 쓰인다** → 아이템 1종, 결과는 복합키로 분기.
  따라서 디지멘탈 단독으로 결과가 결정되지 않는다 — 조회는 반드시 `(Child, 디지멘탈)` 복합키.
- **사용 가능 판정은 레벨이 아니라 매핑 조회다.** `armorResult(childID:digimental:)` 가 값을
  돌려주면 가능, nil 이면 불가. `DigiLevel == .child` 로 판정하면 안 된다 — Tailmon(83)은
  데이터상 Child 지만 작중 Adult 급이라 레벨 축은 경계 사례에서 어긋난다.
- 스프라이트는 Wikimon 아이템 아트(`Digimental_<trait>.jpg`)를 쓴다. 실패 시 이모지 폴백.

## 5. 상점 (upstream 구조 유지)

| 항목 | 가격 | 비고 |
|---|---|---|
| 알 리롤 (보증 없음) | 1.00B | |
| 고급 이상 보증 알 | 2.50B | `graduationTotal` 비율 파생 |
| 희귀 이상 보증 알 | 4.00B | |
| 디지멘탈 (9종 각각) | **1.00B** | 알 리롤 동급 — 9종 전부 9.00B |

**가격은 확률이 아니라 졸업 총량 비율로 매긴다.** upstream 주석에 근거가 있다 —
확률 비율로 매기면 하위 티어 반복 구매가 상위 티어를 모든 축에서 앞질러
상위 티어가 열등재가 된다.

### 디지멘탈 가격 근거

**1.00B (알 리롤 동급)으로 확정.**

- 아머는 **토큰 이득이 0**이므로(§4) 저가여도 파밍 악용이 불가능하다.
  싸게 팔아도 졸업 총량을 우회하지 못한다.
- 9종 전부 모으면 9.00B(~36일). 도감 9칸 확장 비용으로 적정선.
- 아머를 "가볍게 즐기는 곁가지"로 두고 **도감 확장을 장려**하는 방향.

**전설 전용 알은 팔지 않는다 — 이건 설계 선택이다.**

> upstream 의 이유는 **기술적**이었다: `captureRateCeiling` 이 `.legendary` 에 `nil` 을 반환해
> 전설 하한을 `capture_rate` 로 표현할 수 없었다. **우리는 희귀도를 수기 지정하므로 표현 가능하다.**
> 그럼에도 팔지 않는 이유는 최고 등급(오메가몬 부모 2종)을 확정 상품으로 만들지 않기 위해서다.
> 희귀 알(4.00B)이 1/4 로 충분히 겨냥 가능하다.

**한국 정발 더빙명을 쓴다.** (브이몬 · 파일드라몬 · 엔젤몬 …)

- 표시명 매핑 테이블을 앱이 직접 갖는다.
- 조회·저장은 **항상 digi-api ID** 로 한다. 표시명은 출력 직전에만 붙인다.
- 이름 함정은 [`EVOLUTION.md` §5](./EVOLUTION.md) 참고.

### 🚨 확정: 수치 스탯 패널은 제거한다

**결정일 2026-09-21.** upstream 도감 상세에는 종족값·실능력치 바(IV 포함)가 있다.
`CompanionView` 의 `baseStatsSection` / `statsSection` / `statRow` 와 `PokemonStatCalculator`
가 이를 그린다.

**digi-api.com 에는 대응 데이터가 없다.** 실제 응답으로 확인했다:

| 필드 | digi-api | 판정 |
|---|---|---|
| `types` (Warrior, Dragon Man …) | ✅ | 타입 배지로 대응 |
| `attributes` (Vaccine/Virus/Data) | ✅ | 신규 표시 |
| `fields` (Dragon's Roar …) | ✅ | 신규 표시 |
| `skills` (기술명 + 설명) | ✅ | 기술 목록으로 대응 |
| `stats` / `hp` / `attack` / `defense` | ❌ **없음** | — |
| `height` / `weight` | ❌ **없음** | — |

수치가 필요하면 47종을 **손으로 지어내야** 한다. 출처가 없는 값을 만들어 유지보수하는
비용이 UI 한 칸의 가치를 넘고, 설계 문서 어디에도 근거가 없다.

→ **스탯 바·IV 개념을 UI 와 모델에서 제거하고, 도감 상세를 타입·속성·필드·기술 중심으로
재구성한다.** digi-api 가 주는 것만 그린다.

> 참고: IV 는 스탯 바에만 쓰이는 게 아니라 개체 구분에도 쓰인다. 제거 범위는 **표시**가
> 기준이고, 저장 모델에 남은 잔재는 세이브 스키마 작업에서 함께 정리한다.
