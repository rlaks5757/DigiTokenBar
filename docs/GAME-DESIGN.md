# 게임 설계 — 수집 · 육성 · 진화

DigiTokenBar 의 게임 규칙. 진화 데이터는 [`EVOLUTION.md`](./EVOLUTION.md) 참고.

**상위 원칙: upstream(PokeTokenBar)의 토큰 경제를 그대로 쓴다.** 실측 사용량 기반으로
튜닝된 값이라 근거 없이 바꾸지 않는다. 바꾸는 지점만 아래에 명시한다.

---

## 1. 기본 루프 (upstream 그대로)

```
토큰 사용 → 알 부화(5M) → 성장 → 진화 → 졸업 → 도감 등록 → 새 알
```

| 상수 | 값 | 비고 |
|---|---|---|
| 알 부화 임계 | 5,000,000 | 초과분은 부화체 성장에 이월 |
| 졸업 총량 (common) | 750,000,000 | |
| 졸업 총량 (uncommon) | 1,875,000,000 | common × 2.5 |
| 졸업 총량 (rare) | 3,000,000,000 | common × 4 |
| 졸업 총량 (legendary) | 6,000,000,000 | common × 8 |
| 재육성 배율 | 2 | 같은 종 반복 시 |
| 난이도 슬라이더 | 0.1 ~ 2.0 (기본 1.0) | 로그 매핑 |

### 단계별 임계 계산 (upstream 공식 유지)

k개 형태를 가진 라인에서 i번째(1-based) 형태의 성장 비용:

```
threshold(i) = T · i / (k(k+1)/2)     → 합계 = T
```

**졸업 총량 T 는 진화 단계 수와 무관하게 동일하다.** 단계가 많으면 각 단계가 싸진다.
→ Tailmon 라인(k=2)과 Agumon 라인(k=4)의 졸업 비용이 같다. 의도된 동작이다.

---

## 2. 🚨 희귀도 — upstream 방식을 쓸 수 없다

### 문제

upstream 은 PokéAPI `capture_rate` 로 희귀도를 매긴다. **디지몬에는 이에 대응하는 수치가 없다.**

초기 안은 "라인의 최종 레벨 = 희귀도"였다. **실측 결과 이 방식은 상점을 망가뜨린다:**

| 최종 레벨 | 라인 수 | → 희귀도 | 결과 |
|---|---|---|---|
| Adult | 4 (33%) | uncommon | |
| Perfect | 6 (50%) | rare | |
| Ultimate | 2 (17%) | legendary | |
| — | **0** | **common** | ⚠️ **저등급 풀이 비어버림** |

문제 두 가지:
1. **`common` 라인이 0개** → 보증 없는 기본 알이 뽑을 저등급 후보가 없다.
2. **`rare` 이상이 8/12(67%)** → 희귀 알(4.00B)의 "희귀 이상 보증"이 사실상 무보증이다.

즉 **가격 사다리(1B / 2.5B / 4B) 밑에 분포가 없다.**

### 결정: 라인별 희귀도 **수기 지정**

12라인뿐이므로 파생하지 말고 직접 배정한다.
(ANALYSIS.md 의 "크롤러보다 수기 테이블이 낫다" 판단과 동일한 논리)

| 희귀도 | 라인 | 근거 |
|---|---|---|
| common | Piyomon, Tentomon, Palmon, Gomamon | 01 조연 4라인 |
| uncommon | V-mon, Wormmon, Hawkmon, Armadimon | 02 파트너 4라인 |
| rare | Patamon, Tailmon | 작중 비중 높음 |
| legendary | Agumon, Gabumon | Ultimate 보유 + 오메가몬 부모 |

→ 4 / 4 / 2 / 2 분포. 가격 사다리가 정상 동작한다.

> **희귀도는 라인 단위 속성이다.** 개체 레벨이 아니다.
> Agumon 은 Child 지만 legendary 라인이므로 졸업 총량 6B 를 따른다.

### 랜덤 풀 규칙 — 12라인용으로 재정의

upstream `CollectionWeight.adjusted(_:isCollected:)` 는 이미 수집한 종의 가중치를 **1/2** 로 낮춘다.
**이건 649종 로스터 기준으로 튜닝된 값이다.** 12라인에서는 1/12 → 1/11.5 수준이라 사실상 무의미하다.

**결정: 도감 미완성 동안 이미 졸업한 라인을 랜덤 풀에서 제외한다.**

- 12라인을 다 모을 때까지는 **중복 없는 ≤12회 수열**이 된다.
  (균등 1/12 쿠폰 수집이면 특정 2종에 기대 18개 알이 필요하다 — 무한 대기의 원인)
- 도감 완성 후에는 전체 풀로 복귀하고, 그때부터 `repeatGrowthMultiplier = 2` 가 적용된다.
- **등급 보증 알에도 동일하게 적용한다** — 보증 풀에서 졸업분을 뺀다.

#### 제외 기준은 "졸업"이지 "부화"가 아니다

**중복이 발생할 수 있는 경로가 두 개 있다. 둘 다 의도된 동작이다.**

| 경로 | 도감 등록 | 풀에서 제외 | 같은 라인 재출현 |
|---|---|---|---|
| 졸업 | ✅ | ✅ | ❌ (도감 완성 전) |
| **알 리롤 (1.00B)** | ❌ | ❌ | ✅ **가능** |
| **육성 중 포기/교체** | ❌ | ❌ | ✅ **가능** |

upstream 은 리롤한 개체를 "뽑은 적 없던 것처럼" 처리한다 — 도감에도 확률에도 영향이 없다.
**이 성질을 유지한다.** 리롤이 풀을 줄이면 1.00B 로 도감을 깎는 파밍이 되기 때문이다.

> 즉 **"안 뽑힌 라인이 다시 나오는 일"은 없지만, "버린 라인이 다시 나오는 일"은 있다.**
> 리롤은 마음에 안 드는 개체를 넘기는 수단이지, 특정 라인을 겨냥하는 수단이 아니다.

#### 죠그레스·아머 결과는 풀에 영향을 주지 않는다

- 죠그레스 결과(Omegamon 등)와 아머체는 **도감에 등록되지만 알에서 나오지 않는다.**
  랜덤 풀의 단위는 **12개 Child 라인**이다.
- 같은 라인 2회차 육성(§4 아머↔죠그레스)은 **도감 완성 후에만** 가능하다.
  미완성 동안에는 그 라인이 풀에서 빠져 있기 때문이다.

> 이 규칙이 "파피몬이 안 나와서 못 넘어간다"를 구조적으로 막는다.

## 3. 죠그레스 — 도감 게이팅

### 문제

현재 앱은 **육성 중인 개체가 1마리**다. 죠그레스는 2마리가 필요하다.

### 결정: 도감 졸업 기록을 파트너로 인정

```
[육성 중] XV-mon — 죠그레스 임계 도달
[도감]    Stingmon 졸업 기록 있음  →  죠그레스 활성화
          XV-mon + Stingmon → Paildramon
```

**규칙:**
- 파트너는 **소모되지 않는다** — 도감은 재고가 아니라 기록이다.
- 파트너 기록이 없으면 버튼 비활성 + `"Stingmon을 먼저 졸업시켜야 합니다"` 안내.
- `(A, B)` 는 **순서 무관** — 정렬된 키로 정규화해 조회.

### ✅ 죠그레스 결과는 도감에 졸업 등록된다

**이게 없으면 Paladin Mode 가 영구 도달 불가다.** Paladin Mode 의 부모
(Imperialdramon FM, Omegamon)는 **둘 다 죠그레스 결과물**이기 때문이다.

도달 경로:
```
1. Agumon 라인 졸업 → War Greymon 기록
2. Gabumon 라인 졸업 → Metal Garurumon 기록
3. 죠그레스 → Omegamon (도감 등록됨)
4. V-mon/Wormmon 라인 → Paildramon → Imperialdramon FM (도감 등록됨)
5. Imperialdramon FM + Omegamon → Paladin Mode   ← 최종 보상
```

### 파트너 조달 — 등급 보증 알

**보증은 "그 등급 이상"이지 "그 등급대"가 아니다.**
upstream 판정은 `line.rarity.sortRank < tier.sortRank` 로 **하한 미달만 거른다.**

| 알 | 가격 | 실제 풀 | 라인 수 |
|---|---|---|---|
| 기본 (보증 없음) | 1.00B | 전체 | 12 |
| 고급 이상 | 2.50B | uncommon+rare+legendary | 8 |
| 희귀 이상 | 4.00B | rare+legendary | 4 |

**결과: 상위 등급일수록 겨냥하기 쉽고, 중간 등급이 가장 어렵다.**
위에서 희석되지 않는 건 최상위 티어뿐이기 때문이다.

- `legendary`(Agumon·Gabumon) = 오메가몬 부모 2종.
  희귀 알 4.00B 로 **1/4** → 둘 다 모으는 데 기대 ~6개.
- `uncommon`(02 파트너 4라인)은 고급 알을 사도 8라인 중 4라인이라 **50%**.
  → **실질 병목은 Agumon·Gabumon 이 아니라 V-mon·Wormmon 이다.**
  Paildramon → Imperialdramon FM → Paladin Mode 경로가 여기에 걸린다.

## 4. 아머 진화 — 상점 아이템

**디지멘탈을 상점에서 팔고, 사용하면 Child 에서 아머형으로 분기한다.**

### 🚨 단계 수(k)가 분기마다 달라진다

upstream `phaseThreshold(rarity:totalForms:stageIndex:)` 는 **라인당 k가 하나**라고 가정한다.
V-mon 은 정규 4형태 라인 + 아머 분기 3개를 갖는다. → 명시적 규칙 필요.

**결정:**
- 아머 분기의 **k = (현재 단계 index) + 1**. 즉 아머형이 그 라인의 마지막 형태가 된다.
  - 예: V-mon(stageIndex 0)에서 아머 진화 → k=2 → 아머형이 2번째이자 최종 형태.
- **이미 적립된 성장 토큰은 유지된다.** 디지멘탈 사용은 진행도를 리셋하지 않는다.
- 아머형 도달 = **그 라인의 졸업**으로 처리한다. 도감에 등록되고 새 알로 넘어간다.

> ⚠️ **아머는 토큰을 아껴주지 않는다.** `graduationTotal` 은 단계 수 k 와 **무관하게 동일**하다
> (공식이 그렇게 설계됐다 — k가 크면 단계당 비용이 싸질 뿐 합은 T로 같다).
> 실측: V-mon 정규 k=4 와 아머 k=2 모두 졸업 총량 1.88B 로 **차액 0**.
>
> 아머의 이득은 **단계 수가 줄어드는 것**(4→2)과 **도감 9칸 추가**다.
> 따라서 디지멘탈 가격은 "단축분 회수"가 아니라 **도감 확장 콘텐츠 가격**으로 책정한다.

### 🚨 아머 ↔ 죠그레스는 배타적이지 않다 — 퇴화는 없다

원작에서 02 파트너는 아머 진화도 하고 죠그레스도 한다. 단 **아머체에서 죠그레스로 가려면
성숙기로 돌아가야 한다**(V-mon: 아머체 Fladramon ↔ 성숙기 XV-mon 은 다른 분기).

**결정: 퇴화(devolution) 기능을 넣지 않는다.** 대신 **도감 기록이 둘 다 남는 것으로 해결한다.**

- 아머 진화 = 그 **개체**의 졸업. 도감에 아머체가 등록되고 새 알로 넘어간다.
- 죠그레스 파트너 판정은 **도감 졸업 기록**을 본다(§3). 육성 중인 개체가 아니다.
- 따라서 같은 라인을 **두 번 육성**하면 아머체와 성숙기 기록을 둘 다 가질 수 있다.

```
1회차: V-mon → (디지멘탈) → Fladramon 졸업   → 도감: Fladramon
2회차: V-mon → XV-mon 졸업                    → 도감: XV-mon
       → 이제 XV-mon + Stingmon 죠그레스 가능
```

- **진화 트리 UI 는 열람 전용이다.** 도달 가능한 경로를 보여줄 뿐,
  임의 진화/퇴화 버튼은 제공하지 않는다.
- 재육성은 `repeatGrowthMultiplier = 2` 가 적용된다.
- ⚠️ **순서 제약:** §2 랜덤 풀 규칙상 도감 미완성 동안에는 졸업 라인이 풀에서 빠지므로,
  **같은 라인 2회차는 도감(12라인)을 다 채운 뒤에야 가능하다.**
  → 즉 아머를 먼저 쓴 02 파트너의 죠그레스 경로는 **도감 완성 이후로 밀린다.**

> ⚠️ **미해결 트레이드오프:** 이 규칙대로면 아머 진화를 먼저 한 라인의 죠그레스가
> **도감 완성 이후까지 밀린다.** 디지멘탈을 언제 쓸지가 실질적 선택이 되므로
> 의도된 긴장으로 보지만, V-mon·Wormmon 에 걸리면 Paladin Mode 경로가 통째로 늦어진다.
>
> **완화안(플레이 테스트 후 결정):** 죠그레스에 필요한 성숙기 기록이 없는 라인은
> 아머체를 졸업시켜도 풀에서 빼지 않는다 — 즉 **"죠그레스 경로 미완"을 미수집으로 간주**한다.
> 구현 전 이 항목을 먼저 확정할 것.

### 🚨 아머 선택은 결정적(deterministic)이다

upstream 의 분기 선택은 `CollectionWeight.adjusted(_:isCollected:)` 로
**가중 랜덤**이다(이미 수집한 종은 가중치 1/2).

**아머 진화는 이 가중치를 우회한다.** 사용자가 디지멘탈을 골라 쓰는 행위이므로,
`(Child, 디지멘탈)` 복합키가 결과를 **확정**한다. 랜덤 없음.

> 정규 진화 분기는 기존 가중 랜덤을 그대로 쓴다. 우회는 아머 경로 한정.

### 디지멘탈 아이템

- `ItemKind` enum 에 추가한다(현재 `rareCandy` / `mint` / `shinyCharm`).
- **성실 디지멘탈은 V-mon·Armadimon 양쪽에서 쓰인다** → 아이템 1종, 결과는 복합키로 분기.
- 스프라이트는 PokéAPI 아이템 경로를 쓸 수 없다 → 이모지/로컬 도형 폴백.

## 5. 상점 (upstream 구조 유지)

| 항목 | 가격 | 비고 |
|---|---|---|
| 알 리롤 (보증 없음) | 1.00B | |
| 고급 이상 보증 알 | 2.50B | `graduationTotal` 비율 파생 |
| 희귀 이상 보증 알 | 4.00B | |
| 디지멘탈 | 미정 | 아머 경로 단축분을 회수하는 선 |

**가격은 확률이 아니라 졸업 총량 비율로 매긴다.** upstream 주석에 근거가 있다 —
확률 비율로 매기면 하위 티어 반복 구매가 상위 티어를 모든 축에서 앞질러
상위 티어가 열등재가 된다.

**전설 전용 알은 팔지 않는다 — 이건 설계 선택이다.**

> upstream 의 이유는 **기술적**이었다: `captureRateCeiling` 이 `.legendary` 에 `nil` 을 반환해
> 전설 하한을 `capture_rate` 로 표현할 수 없었다. **우리는 희귀도를 수기 지정하므로 표현 가능하다.**
> 그럼에도 팔지 않는 이유는 최고 등급(오메가몬 부모 2종)을 확정 상품으로 만들지 않기 위해서다.
> 희귀 알(4.00B)이 1/4 로 충분히 겨냥 가능하다.

## 6. 이름 표기

**한국 정발 더빙명을 쓴다.** (브이몬 · 파일드라몬 · 엔젤몬 …)

- 표시명 매핑 테이블을 앱이 직접 갖는다.
- 조회·저장은 **항상 digi-api ID** 로 한다. 표시명은 출력 직전에만 붙인다.
- 이름 함정은 [`EVOLUTION.md` §5](./EVOLUTION.md) 참고.
